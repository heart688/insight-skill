# 从问题到全文的写作模式

用于起草、重写或比较段落功能。下列顺序是可调整的组织工具，不能覆盖用户的研究事实和指定结构。

## 先分清观察、问题、判断和方案

- **观察**：材料或诊断显示发生了什么。个别案例可以提出问题；不能代表总体发生率。
- **问题**：在什么约束下，现有处理仍缺少哪项能力。
- **判断**：哪些对象需要区分、哪些信息值得保留、什么依据应参与决策，或哪种设计选择值得检验。
- **方案**：怎样实现这个判断，以及为此接受了哪些取舍。

方法有效不自动证明原先假设的所有原因；权重变化不自动证明变化有益；一项对照胜出不自动证明某类方法普遍失败。叙述应在这些层级间明确推进。

可用以下内部记录防止写作漂移：

```text
实际任务与限制：
主要贡献类型：
观察及来源：
最近的合理替代方案及其未解决之处：
值得检验的问题：
核心判断，一句话：
方法怎样回应：
最强判别证据：
可能改变解释的结果：
读者最后能带走的认识：
```

尚无来源的场景或观察标记为待核实。某字段不适用于当前研究时调整，不为填满模板创造事实。

识别研究类型时可参考 [公开顶会论文的不同论证方式](top-conference-patterns.md)。简化、规模、系统、任务与资源、理论等研究未必以失效案例起步。先问本研究改变了什么，再选择后面适用的段落功能。

## Introduction 的四项功能

### 场景与需求

应用和系统研究可由实际决策或服务开始，解释预测、识别、检索或推断怎样影响它。选一个对后续问题有用的约束，例如标签不足、环境变化、延迟限制、覆盖不足。基础研究可由待检验能力或知识问题进入，理论研究可直接建立数学目标。段尾让读者理解为什么要研究该设置。

背景例子应解释约束，不能只是应用列表。不要凭空宣称某方法已在真实服务部署，也不要为了契合会议把任务换成另一个研究问题。

### 可见障碍与研究问题

从具体观察指出困难，再解释既有依据、假设或流程为何在该条件下不充分。必要时用诊断图区分个别现象和总体证据。段末提出问题，问题应能由后续设计和证据回答。

选择一个最接近的合理方案比较，说明它已解决什么、尚未满足什么。例如“现有流程能完成目标，但额外阶段带来成本”“当前架构在小数据下有效，尚不清楚扩大数据后会怎样”。不要只写某领域从未用过一种技术，也不要要求每篇论文都反驳一个错误假设。

若观察只建立一种可能性，保持这种强度。不要从两个案例直接跳到“现有方法必然失败”。

### 核心认识

把前面的问题细化为一个值得检验的区分或设计原则。说明原本混在一起的对象分别承担什么职责，或新增证据为何与任务更直接相关。读者此时应能理解解决方向，即使还不知道公式与模块名。

若这段读起来像实现清单，先移开参数名，重写成“需要什么 → 为什么 → 由此研究什么”。最后再自然引出方案。

### 方法与贡献

按问题的推进顺序介绍方法，每句话完成一项功能：输入提供什么、核心机制做什么、产生怎样的结果、怎样适应约束。标准编码器、归一化或预测头无需夸大，也不替作者虚构第三方骨干。

贡献之间不能只是换个说法重复框架。研究认识、方法实现和证据发现分别承担不同任务。实验贡献应说得到什么认识，不能只说做了很多实验。

## Method 的自然生长

Overview 先讲设计原则如何落实，再给完整信息流，指出核心机制的位置。

可以先把约束转成少量设计目标，例如保持原目标、允许变长输入、满足延迟条件。核心操作应能响应这些目标，目标之间的取舍也应可见。无需为标准实现逐项编造动机。

每个核心小节推进一个问题。例如：

```text
输入中需要识别什么信息
→ 怎样表示这些信息
→ 当前表示仍缺少什么
→ 怎样构造补充证据或完成决策
→ 怎样在资源或监督约束下执行
```

操作前给理由，公式后说明定义与作用。复杂公式允许必要展开，但不能连续甩出公式让读者自己推导设计目的。标准细节写到足以理解和复现，不用小节数量制造方法深度。

说明某方案为合理实现，还是由已有对照支持的选择。前文提出的是可能性，后文选定实现时，要交代选择依据或将其表述为待检验设计；不靠 `therefore` 假装逻辑已经完成。

分清信息依赖与研发时间顺序。正文可按读者理解所需的先后组织，不必模拟作者真实发现顺序，也不能宣称事后结论是预先提出的假设。涉及多个阶段时，解释前一阶段给后一阶段留下什么；训练期、推理期和资源建设各自贡献用相应证据检验。

## Experiments 的判别设计

为每个主要主张指定能区分解释的证据：

- **整体有效性**：适当竞争方法、共同任务、合理协议、重复结果；建立任务表现。
- **信息或组件贡献**：删除、替换或输入干预，并控制相关容量与预算；定位收益来源。
- **核心判断**：直接比较主张所区分的对象，或改变核心机制而保持其他条件；回答本文真正的问题。
- **机制分析**：模型行为、预测变化与干预相联系；可视化本身不等于因果证明。
- **部署条件**：资源测量、规模、数据量或环境变化；说明优势和边界。

并非每篇都需要五组独立实验。已有一组结果回答多个问题时，明确其作用；重复性对照合并。理论工作用条件、命题、证明与反例承担对应任务。

从材料中选择最有判别力的一两项展示作为主要论证支点，不规定图号。可以是控制变量对照、规模曲线中的排序转折、受同一约束的取舍曲线或直接检验理论预测的结果。其他实验承担总体效果、排除解释或界定范围；不要求所有图表重复同一句结论。

机制与结果之间需要中间关系。系统优化可以展示瓶颈减少、可承载工作负载增大、最终吞吐或延迟改善；质量与成本共同构成目标时应同时比较。若已有证据没有验证其中某环节，解释应停在得到支持的位置，不自动启动新实验。

结果解释按“本组检验什么 → 关键发现 → 支持什么 → 哪些结果限制解释”推进。没有例外影响主张时，不强行添加防御段。数值只选能表达判断的代表项，完整值留在图表。

局部更优策略要融入认识。例如某设计接近全量更新且减少可训练参数，支持这种适配方式可行；它未必支持精度最佳、训练最快或所有任务都应采用它。

不要只靠参数更少推出显存更低、复杂度更低推出实测更快，或平均误差较小推出显著差异。对应结论需要对应测量。

## Abstract、Related Work 和 Conclusion

Abstract 保留故事骨架，删掉非核心操作说明。首次接触模型名时，读者应能理解它要完成的任务；其具体处理方向可在相邻句自然建立。作者要求先问题后方法时按该要求处理；不要把模型名必须晚出现变成所有论文的写作定律。

Related Work 选择与主问题有关的比较轴，如关系怎样形成、证据怎样使用、知识怎样迁移、预算怎样分配。每类介绍后说明本文研究的选择，避免逐篇列表后突然宣布方法。

Conclusion 用得到支持的认识回应 Introduction 的问题。可以说明方法让什么成为可行，但不重新列出每张表、每个模块和每条数字。未来工作按需要写，不用惯常句子填尾段。

标题概括贡献对象，Abstract 保留核心关系，Introduction 展开理由，Method 给出精确实现，结果界定它成立的条件，Conclusion 收回得到支持的认识。沿途保持关键概念指代一致；通过不同功能推进理解，不靠同义词换写和反复口号制造连贯。

## 任务中的创新怎样写

已有技术的新任务应用、机制组合、约束下的适配和新的实验认识，都可能成为贡献。写清此前处理缺少什么，本研究改变什么，为什么这个改变与任务有关，证据支持什么。

不要求每个算子首次发明，也不把重命名或换数据集自动当作创新。说明既有技术基础与自己的问题、设计和验证，创新强度由具体差异及证据决定。

## 跨领域校准示例

以下为假设性说明，不是已完成研究或可引用结果。

**多条件文档检索**：真实需求是回答包含多个条件的问题；困难是高相关片段可能重复覆盖同一条件；值得检验的认识是相关性和条件覆盖承担不同职责；设计用相关性获取候选，再管理覆盖；证据比较同长度上下文、去除覆盖机制及答案遗漏情况。不要未经实验写成所有相似度检索都无效。

**动态推理预算**：真实需求是在延迟约束下处理难度不同的输入；困难是固定计算量不能同时充分处理难例和节省易例成本；判断是计算预算应随可观测难度分配；设计先估计难度再分配计算；证据在相同总预算下比较误差、尾延迟和分配行为，并保留难度估计失效的条件。

两例使用不同机制，保留相同的写作关系：任务约束产生具体问题，问题引出可检验原则，方法实现原则，证据检验认识。
